CBoot-CLI 最终设计规范 v2.0

一、核心理念与运行模式

模式 命令 行为
交互模式 cboot <项目名> 创建项目目录，进入向导式REPL（命令简短，缺失信息由AI式问答补全）。
批处理模式 cboot 读取当前目录的 .cboot 脚本，逐行执行（不创建新目录，脚本需用完整行内标志）。
强制标志 -f 交互模式：删除重建项目目录；批处理模式：静默覆盖冲突文件。

二、统一作用域体系（核心架构）

一切皆作用域（Scope），支持 cd 无缝导航：

作用域类型 说明 可容纳的子项
模块（Module） 物理目录映射 子模块、函数、类型、宏、依赖、资源
函数（Function） C函数 参数（add）、局部变量（add）
类型（Type） typedef struct 结构体成员（add）

```c
typedef enum { SCOPE_MODULE, SCOPE_FUNCTION, SCOPE_TYPE } ScopeType;

typedef struct Scope {
    ScopeType type;
    char *name;
    struct Scope *parent;
    struct Scope **children;  // 子作用域（子模块/嵌套类型等）
    int child_count;
    char *comment;            // 当前作用域的描述注释
    struct Comment *comments; // 子项注释（参数/成员）
    int comment_count;
} Scope;
```

三、交互命令全集（含新增 rm）

3.1 创建与定义（进入向导模式）

命令 语法 说明 向导内容
mod mod <名称> 创建子模块 询问模块注释。创建后自动 cd 进入。
func func <返回类型> <名称> 创建函数 询问函数注释 → 循环添加参数（含注释）→ 循环添加局部变量（含注释）。创建后自动 cd 进入。
type type <名称> 创建结构体类型 询问类型注释 → 循环添加成员（含注释）。创建后自动 cd 进入。
def def <宏定义> 添加宏 询问宏注释。
add add <类型> <名称> 在当前作用域添加子项 函数内=参数；类型内=成员。询问注释。
im im <目标> 导入依赖 若目标是模块名 → 记录模块依赖；若带<>或"" → 记录头文件。自动去重。

3.2 导航与查看

命令 语法 说明
cd cd <路径> 支持模块/函数/类型名；支持 ..；支持绝对路径如 /core/add。
ls ls 列出当前作用域下的所有子项（含类型标注）。

3.3 注释（短命令设计）

命令 语法 说明
cmt cmt "文本" 为当前作用域本身添加/修改注释。
arg arg <参数名> "文本" 为当前函数的某个参数添加注释（仅限函数作用域）。
mem mem <成员名> "文本" 为当前类型的某个成员添加注释（仅限类型作用域）。

所有 cmt/arg/mem 在脚本模式中对应 --comment、--arg、--member 标志。

3.4 资源管理

命令 语法 说明
res res <资源文件路径> 进入向导：选择目标模块（默认当前）→ 勾选模式（普通/-h/-bitmap，可多选）。

3.5 🔥 新增：删除命令 rm（移除错误定义）

命令 语法 说明
rm rm <名称> 智能删除当前作用域下匹配的名称。若匹配到多个类型，进入歧义消除向导。
rm -f rm -f <名称> 强制删除，若有歧义则报错退出（不询问）。

rm 详细行为：

· 在当前作用域（Scope *current）的所有子项中查找 <名称>：
  · 匹配子作用域（模块/函数/类型）→ 递归删除整棵子树。
  · 匹配参数/局部变量/成员→ 从父作用域的列表中移除。
  · 匹配宏→ 从模块的宏列表中移除。
  · 匹配依赖→ 从模块的依赖列表中移除。
  · 匹配资源引用→ 从模块的资源引用列表中移除。
· 歧义消除示例：
  ```text
  CBoot/core/add> rm a
  找到多个同名项：
  1. 参数 int a
  2. 局部变量 int a
  请选择要删除的编号（输入0取消）： 1
  已删除参数 int a
  ```
· 若当前作用域是函数，rm a 会优先匹配参数，其次是局部变量。
· 若当前作用域是类型，rm x 直接删除成员 x。

3.6 生成与退出

命令 语法 说明
gen gen generate 的短别名。生成所有代码、CMake、文档。
exit exit 退出（若未gen则警告）。

四、文件生成规则（三大铁律）

规则 内容
规则A（目录判定） 模块只要有子模块或被强制下沉，就拥有同名物理目录。
规则B（文件落位） 若模块 has_directory == true，其 .c/.h 放入 模块目录/模块名.c；否则直接放在父目录下。
规则C（冲突自动下沉） 若创建子模块 X 时，父目录已存在 X.c/X.h，则子模块 X 强制拥有目录，并将父模块自身的文件迁移为 X/X.c。

最终目录示例：

```
MyProject/
├── CMakeLists.txt
├── main.c
├── src/                # 根级模块的 .c（若无子模块，直接放根目录）
│   └── core.c
├── include/
│   └── core.h
└── core/               # 模块 core（因有子模块，建立了目录）
    ├── core.c          # core 自身的代码（被规则A从根目录迁移而来）
    ├── core.h
    └── utils/          # 子模块 utils（无冲突，直接建目录）
        └── utils.c
```

五、资源管理（位掩码组合模式）

```c
typedef enum {
    ASSET_MODE_HEX    = 1 << 0,   // -h: xxd 转 .h
    ASSET_MODE_BITMAP = 1 << 1    // -bitmap: ffmpeg 转 .bmp
} AssetMode;
```

· 命令示例：res logo.png → 向导中可同时勾选 -h 和 -bitmap。
· 物理存储：原文件只复制一次到 /res/logo.png。
· CMake 生成：去重后同时生成 xxd 和 ffmpeg 两条 add_custom_command。
· 模块代码：按勾选模式，自动插入 #include "logo_hex.h" 和/或 #define LOGO_BMP_PATH "res/logo.bmp"。

六、依赖管理（im 命令）

· 模块级依赖：im core → 当前模块依赖 core，自动在 .c 顶部插入 #include "core.h"。
· 系统头文件：im <stdio.h> → 记录到模块的 includes 列表（全局去重）。
· 循环检测：gen 时检测依赖图，发现循环依赖报错并提示。
· CMake 生成：自动处理包含目录顺序和链接顺序。

七、注释与文档生成

7.1 注释存储

注释挂在 Scope 的 comment 和 comments 链表上，与代码元素一一对应。

7.2 生成内容

执行 gen 时：

1. 遍历作用域树，生成 docs/api.md（Markdown）和 docs/project.man（troff）。
2. 在 CMakeLists.txt 中注入文档构建规则：
   · 检测 pandoc → 生成 .html / .pdf。
   · 检测 groff → 生成 .1 手册页。
3. 创建 docs 自定义目标，主目标依赖它。

八、.cboot 脚本模式（批处理）

· 无参启动 cboot 自动加载当前目录的 .cboot。
· 语法：每行一条完整命令，使用行内标志（因为无交互）：
  ```bash
  # 脚本示例
  project MyServer                    # 设置 CMake 项目名
  mod core --comment "核心引擎"
  func int add int a int b --comment "加法" --arg a "左值" --arg b "右值"
  type Point --comment "坐标" --member int x "X轴" --member int y "Y轴"
  im utils
  res logo.png --targets core utils --mode hex,bitmap
  rm func add                         # 删除刚才定义的函数
  gen
  ```
· 标志对应关系：
  · --comment → 作用域注释
  · --arg <名> "描述" → 函数参数注释
  · --member <名> "描述" → 类型成员注释
  · --targets <模块列表> → res 的目标模块
  · --mode <模式列表> → res 的模式（hex/bitmap/hex,bitmap）

九、数据结构总览（C语言定义）

```c
// ---------- 注释 ----------
typedef struct Comment {
    char *target;    // 参数名/成员名
    char *text;
} Comment;

// ---------- 作用域 ----------
typedef enum { SCOPE_MODULE, SCOPE_FUNCTION, SCOPE_TYPE } ScopeType;

typedef struct Scope {
    ScopeType type;
    char *name;
    struct Scope *parent;
    struct Scope **children;
    int child_count;
    char *comment;
    Comment *comments;
    int comment_count;
} Scope;

// ---------- 模块 ----------
typedef struct Module {
    Scope base;
    int has_directory;
    int forced_subdir;
    char **macros;          // #define 定义
    int macro_count;
    char **includes;        // 系统/本地头文件
    int include_count;
    char **dependencies;    // 依赖的模块名
    int dep_count;
    AssetRef *asset_refs;   // 资源引用列表
    int asset_ref_count;
} Module;

// ---------- 函数 ----------
typedef struct Function {
    Scope base;
    char *return_type;
    char **params;          // 参数声明，如 "int a"
    int param_count;
    // 局部变量用 children Scope 存储（type = SCOPE_VARIABLE）
} Function;

// ---------- 类型 ----------
typedef struct Type {
    Scope base;
    char **members;         // 成员声明，如 "int x"
    int member_count;
} Type;

// ---------- 资源 ----------
typedef struct AssetRef {
    char *asset_name;
    int mode_flags;         // HEX | BITMAP
} AssetRef;

// ---------- 项目 ----------
typedef struct Project {
    char *name;
    Module *root;
    Scope *current;         // 当前所在作用域
    char **copied_assets;   // 已复制资源去重表
    int asset_count;
} Project;
```
